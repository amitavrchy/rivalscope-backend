# Synthetic data provenance

`src/seed.ts` installs initial product configuration; it is not customer or market data. Existing plan/pack values are retained. `src/seed-demo.ts` is a separately invoked, locally authored fictional dataset: 3 isolated research studios, 24 nonprivileged analyst/viewer identities, 24 projects and 144 fictional comparison candidates. Reserved `.invalid` addresses/domains and explicit synthetic labels distinguish these from real users, customers and research findings. No provider calls, completed research runs, payments, evidence quotations or verified claims are fabricated.

Run `npm run db:seed`, then optionally `npm run db:seed:demo`. A deterministic namespace creates UUIDs; each studio is inserted atomically under a PostgreSQL advisory lock. If a studio already exists it is skipped entirely, so a rerun cannot change passwords, memberships, deleted projects or business edits. An ID/email/slug collision fails rather than overwriting another row. The seed does not repair manually deleted portions of an existing studio. Sample studios can exceed default free-plan quotas; they are historical demonstration records, not paid entitlements. Launching new work remains subject to normal authorization, verification and quota checks.

Accounts have randomly generated, discarded password hashes, unverified email and no platform-admin flag. No seed creates a login session or grants an owner/platform role. Access must be granted deliberately by an operator. No private sample rows are bundled into the public frontend. Static marketing content already renders without the API; authenticated records remain server-authoritative with in-memory revalidation only.

Production execution requires explicit `ALLOW_PRODUCTION_SEED` approval, including direct seed commands. Startup seeding is disabled unless separately opted in. After initial seeding, `npm run db:seed:verify` verifies that all selected stored rows, including password hashes, remain identical on rerun. Local data lives in the `rivalscope-readiness-pg` Docker volume, not inside the API container. Keep this local demonstration volume; it is not a production database or backup.
